# Homebrew tap for WeMessage

This directory is the source of the cask published to the `raybman/homebrew-wemessage`
tap. Nothing in here is hand-edited: `homebrew/Casks/wemessage.rb` and
`homebrew/cask.lock.json` are both generated by `pnpm release:cask` (see
`tools/release/bin/cask.mjs`), which itself calls the pure renderer at
`tools/release/src/cask.ts`. `test/release/cask.spec.ts` row 5 checks that the
committed cask on disk still equals what the renderer produces from the
committed lock file, so a hand edit here would be caught, not just discouraged.

## What is in this directory

- `Casks/wemessage.rb`: the cask itself, in the stanza order Homebrew's own
  `brew style` cop expects (`version, sha256, url, name, desc, homepage,
livecheck, depends_on, depends_on, app, binary, binary, uninstall, zap,
caveats`).
- `cask.lock.json`: the two inputs that change release to release,
  `{version, sha256}`. Everything else the renderer needs (the tracked
  GitHub repo, the app and binary names, the launch agent label) is a fixed
  fact baked into the renderer, not read from this file.
- `README.md`: this file.

The `sha256` currently committed in `cask.lock.json` is a placeholder
(64 zeros), not the digest of a real packed DMG. It is deliberately not the
digest of an empty string: `brew audit` recognises that specific value as an
accidental placeholder and refuses it outright ("cannot use the sha256 for
an empty string"), which is exactly the kind of mistake a real placeholder
should not also make. Scenario 10 ships the renderer, the CLI, and this
directory's shape; it does not ship a signed, notarised release artefact.
Scenario 12 (release smoke) is where a real packed DMG first exists in this
repo and `pnpm release:cask --dmg <path>` is run against it for real,
replacing this placeholder with the digest of that artefact.

## Regenerating the cask locally

With an explicit version and digest, no packed DMG required:

```
pnpm release:cask --version 1.0.0-rc.1 --sha256 <64 lowercase hex characters>
```

Or from a built, unsigned DMG named the way the release workflow produces one
(`WeMessage-<version>-arm64-UNSIGNED.dmg`), which also derives `version` from
the filename and computes `sha256` from the artefact's own bytes:

```
pnpm release:cask --dmg dist-pack/WeMessage-1.0.0-arm64-UNSIGNED.dmg
```

Both forms accept `--repo <owner/name>` to override the tracked GitHub repo;
it defaults to `raybman/WeMessage`.

## Standing up the tap

The tap this cask ships to is a separate repository, `raybman/homebrew-wemessage`,
populated by the pull request `.github/workflows/release.yml` opens against it
on every tagged release. To create the tap for the first time:

```
brew tap-new raybman/wemessage
cp homebrew/Casks/wemessage.rb "$(brew --repo raybman/wemessage)/Casks/wemessage.rb"
```

## Installing WeMessage once the tap exists

```
brew tap raybman/wemessage
brew install --cask wemessage
```

## Verifying the cask before it ships

The same two checks `test/release/cask.spec.ts` row 7 runs are available on
the command line, and both need to exit 0 before a release goes out:

```
brew style --cask homebrew/Casks/wemessage.rb
brew audit --cask --strict --online=false homebrew/Casks/wemessage.rb
```

## Uninstalling

```
brew uninstall --zap wemessage
```

`--zap` additionally removes WeMessage's application support files, logs,
preferences, and saved state, in addition to the ordinary uninstall's launch
agent teardown. See the `uninstall` and `zap` stanzas in `Casks/wemessage.rb`
for the exact paths.
