Uninstall

Three things to remove and one order to remove them in: the background agent, the app, and the state directory. Disconnect is real here, so this page is the whole list rather than the polite half of it.

Homebrew

brew uninstall --cask wemessage

The cask stops and removes the background service and deletes the app. It leaves your state alone, which is the conservative default and not an oversight. If you want the state gone too, do the third step below afterwards.

By hand, in order

Order matters exactly once: stop the background service before you delete the app it points at, or launchd spends a while trying to start something that is no longer there.

1. The LaunchAgent

wemessaged service uninstall

Unloads the agent and removes ~/Library/LaunchAgents/sh.wemessage.gateway.plist. If you never installed the service, skip this: the app was supervising the daemon itself and quitting the app already stopped it. Keep it running explains the difference.

2. The app

rm -rf /Applications/WeMessage.app

3. The state

rm -rf ~/Library/Application\ Support/WeMessage ~/Library/Logs/WeMessage

That first path is the default value of WEMESSAGE_DIR, the one directory WeMessage keeps anything in. It holds your settings, your rules, the queued and sent drafts, the hash-chained audit log, and the adapter token hashes. Nothing of yours lives anywhere else.

If you set WEMESSAGE_DIR yourself, remove that directory instead. The daemon, the CLI, and the app all read the same variable, so a custom value means the default path above is empty and the real state is wherever you pointed it. wemessaged service status --json prints the directory in use if you no longer remember.

Revoke the permissions

Deleting an app does not remove the grants you gave it. In System Settings, Privacy and Security, remove WeMessage from Full Disk Access and from Automation. Worth doing if you are removing the app for good, and worth skipping if you plan to reinstall, since you would only be granting them again.

What is left behind

Nothing. WeMessage never wrote to Apple's message database, never created an account, and never uploaded anything, so there is no server-side copy to ask about and no remote session to end. The three paths above are the whole footprint.

If you routed messages to a hosted agent, that service has whatever you sent it, exactly as it would from any other client you gave that access to. Removing WeMessage does not reach into somebody else's logs, and no uninstaller could.
